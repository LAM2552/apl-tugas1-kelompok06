#### U7. Architecture Decision Records (ADR)

**ADR 001: Pendelegasian Penyimpanan Berkas ke Cloud Storage**

- **Status:** Disetujui
    
- **Konteks:** Dokumen fisik rentan hilang, dan server kampus sering _down_ saat _deadline_ karena tidak kuat menahan beban penyimpanan dan _bandwidth_ dari ribuan berkas.
    
- **Keputusan:** Memindahkan penyimpanan _file_ ke _Cloud Storage API_ (_Data Access Layer_). Database lokal hanya menyimpan URL dokumen.
    
- **Konsekuensi:**
    
    - _(+)_ Beban server berkurang drastis (layanan stabil) dan dokumen dijamin aman dari kehilangan.
        
    - _(-)_ Muncul ketergantungan pada _cloud_ pihak ketiga (jika API gangguan, fitur unggah lumpuh).
        


**ADR 002: Kombinasi Pola Layered dan Pipe-and-Filter**

- **Status:** Disetujui
    
- **Konteks:** Aturan seleksi beasiswa itu sekuensial (bertahap) dan rutin berubah. Jika menggunakan monolitik, mengubah aturan berisiko merusak antarmuka (UI) atau basis data.
    
- **Keputusan:** Memakai arsitektur _Layered_ (memisahkan UI, Logika, Data). Khusus pada modul Logika, dipakai _Pipe-and-Filter_ untuk alur validasi dan _scoring_.
    
- **Konsekuensi:**
    
    - _(+)_ Modifiabilitas sangat tinggi. Filter aturan baru mudah disisipkan tanpa merombak sistem atau merusak UI (_Non-Risk_).
        
    - _(-)_ Ada sedikit tambahan latensi (_overhead_) karena data harus dibaca dan diproses melewati banyak lapisan dan _filter_ secara berurutan.
